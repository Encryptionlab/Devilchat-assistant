# 上下文膨胀控制 & 会话摘要写入通路

Version: 1.0 | 2026-07-26

---

## 一、问题

### 1.1 会话摘要被孤立

每次 Conversation 关闭时，系统通过 LLM 生成摘要（summary + outcome + key_points），存入 `conversations.json`。但 `relationship_state.json` 中的 `近期关键事件` 字段**只在 bootstrap 引导时写入一次**，之后永不更新。

后果：系统用了一个月后，所有 LLM prompt 中的"近期事件"仍然是 bootstrap 时的旧数据，近期发生的重要事件（"她考试失利"、"她妈催婚"）虽然在各次 Conversation 摘要里，却从未进入关系记忆层。

### 1.2 长期记忆字段缺乏上限

`近期关键事件`、`unresolved_topics`、`recurring_topics` 等字段会随着使用累积。其中 `recurring_topics` 的衰减机制（`apply_decay()`）已实现但从未调用，`近期关键事件` 此前没有写入通路也就没有膨胀，现在写入通路打通后需要上限控制。

---

## 二、方案

### 2.1 写入通路：MemoryUpdater 规则 5

在 `MemoryUpdater.update()` 中新增规则：

```
触发条件：Conversation 关闭 && topic != "daily" && summary 非空
动作：将 summary 追加到 relationship_state.json 的 近期关键事件 列表
上限：10 条，FIFO（超出时移除最旧条目）
```

过滤 `daily` 话题的原因：日常闲聊（"吃了吗""在干嘛"）的摘要不构成"关键事件"，不应进入长期记忆。

### 2.2 膨胀控制

| 字段 | 控制方式 | 上限 |
|------|---------|------|
| `近期关键事件` | FIFO，新事件顶掉旧事件 | 10 条 |
| `recurring_topics` | 启动时 `apply_decay()`，30 天降权/60 天移除 | 无硬上限，自然衰减 |
| `unresolved_topics` | 已有规则 4 在 repaired 时清理 | 无硬上限，依赖修复 |
| `messages_log` | 已有硬截断 | 100 条/会话 |
| `已关闭会话` | 已有 FIFO | 50 个 |

### 2.3 启动时衰减

`backend/dependencies.py` 的 `init_services()` 新增 `_run_startup_decay()`：

- 读取 `conversations.json`，计算每个 `recurring_topic` 的最近出现天数
- 调用 `MemoryUpdater.apply_decay(ages)` 清理过期话题
- 超过 60 天未出现 → 从 `recurring_topics` 移除
- 超过 30 天 → 记录日志（MVP 阶段不改变数据结构）

## 三、改动清单

| 文件 | 改动 | 行数 |
|------|------|------|
| `src/memory_updater.py` | 新增规则 5：非 daily 话题关闭时 summary → `近期关键事件`，FIFO 上限 10 | +12 |
| `backend/dependencies.py` | `init_services()` 新增 `_run_startup_decay()`，启动时清理过期 recurring_topics | +35 |

已有调用链不需要改：`_handle_conversation_closed()` 本来就调用 `MemoryUpdater.update()` + `save()`，规则 5 自动生效。

---

## 四、数据流变化

```
之前：
Conversation 关闭 → summary 写入 conversations.json
                  → MemoryUpdater 更新 recurring_topics / unresolved_topics / conflict_level
                  → 近期关键事件 无人更新 ← 缺口

现在：
Conversation 关闭 → summary 写入 conversations.json
                  → MemoryUpdater 更新 recurring_topics / unresolved_topics / conflict_level
                  → 规则 5: topic != "daily" → summary 写入 近期关键事件（≤10 条 FIFO）
                  → 下一次 LLM 调用的 prompt 自动包含最新的近期事件
```
