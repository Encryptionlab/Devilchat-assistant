# 100 条消息压力测试 —— 问题分析报告

> 测试时间：2026-07-26 | 118 条消息，模拟 14 天 | 354 次 LLM 调用，0 失败

---

## 一、测试场景概览

模拟一对暧昧期大学生在考研备考期间的日常聊天，涉及 6 种话题交替：

| 话题 | 场景举例 |
|------|---------|
| exam | 复习焦虑、刷题、模考 |
| daily | 吃饭、天气、闲聊 |
| relationship | "你会等我吗""我不想异地""我们以后会在一起吗" |
| conflict | "你从来都不主动""你是不是不想理我了" |
| dating | 约会安排、电影、出游 |
| family | 父母催考研、弟弟问题目 |

## 二、问题 1：话题检测几乎失效（严重程度：致命）

### 数据

```
daily          104  ████████████████████████████████████████████████████  88%
exam            12  ██████                                               10%
relationship     2  █                                                    2%
conflict         0                                                       0%
dating           0                                                       0%
family           0                                                       0%
```

### 具体漏判案例

| 原消息 | 当前判为 | 应为 |
|--------|---------|------|
| "你从来都不主动" | daily | **conflict** |
| "你是不是不想理我了" | daily | **conflict** |
| "每次都是我找你，你都不找我" | daily | **conflict** |
| "今天是我们认识100天" | daily | **relationship** |
| "你会等我吗" | daily | **relationship** |
| "我不想异地" | daily | **relationship** |
| "我爸妈打电话问我考得怎么样" | daily | **family** |
| "我妈今天又问我考研的事了" | daily | **family** |
| "这周末我们出去玩吧" | daily | **dating** |
| "电影好感人啊" | daily | **dating** |

### 根因

当前 `TOPIC_KEYWORDS` 表只有约 60 个关键词，覆盖不足。例如：

- `relationship` 有"我们""感情"但缺"在一起""等你""异地""未来""以后"
- `conflict` 有"吵架""你总是""不理我"但缺"不主动""不想理""你从来不""根本不"
- `dating` 有"约会""看电影"但缺"出去玩""周末""一起"
- `family` 有"妈""爸"但缺"我妈""我爸""父母""家里人"（消息中是"我妈"而非"妈"）

### 连锁影响

话题检测是所有下游的入口：
- **对话边界**：topic 分不出来 → 所有消息都归 daily → 无法触发 topic_switch 条件 → 巨型对话（10 天 250h 不关闭）
- **摘要质量**：summarizer 收到混杂话题的巨型消息列表，只能给出模糊摘要
- **MemoryUpdater**：recurring_topics 永远检测不到 conflict/relationship/dating 的重复出现
- **策略选择**：部分策略卡依赖 topic 做判断，topic 不对 → 策略不对

### 候选方案

**方案 A：扩充关键词表（低成本）**
- 将现有 60 个关键词扩展到 200-300 个
- 加入常见口语变体（"不主动""根本不在乎""异地"等）
- 估算工时：2-3 小时

**方案 B：LLM 话题检测（高质量）**
- 在 message_understanding 的 system prompt 中增加一个 `topic` 字段
- LLM 同时输出 topic 标签，替代纯关键词匹配
- 代价：不增加额外 LLM 调用（已有调用中多加一个字段），但 prompt 稍长
- 估算工时：1 小时（改 prompt + 改解析逻辑）

**方案 C：混合（关键词初筛 + LLM 兜底）**
- 关键词匹配置信度高时直接用
- 关键词无匹配或低置信时，在 message_understanding 中附带判断 topic
- 代价：逻辑复杂度增加
- 估算工时：3-4 小时

## 三、问题 2：unresolved_topics 严重污染（严重程度：高）

### 数据

118 条消息后 `unresolved_topics` 堆积了 15 条，其中大量误判：

```
误判示例：
  '她最后道晚安结束对话'              ← 正常结束语，不是未解决问题
  '她询问了对方的复习情况'            ← 日常提问
  '感叹一周一周过得好快'              ← 闲聊感慨
  '她提醒对方早点睡不要熬夜'          ← 关心话语
  '弟弟来问她题目，她自己也不会'      ← 日常分享

合理示例：
  '今天是双方认识100天的纪念日但用户没有记得'  ← 确实未解决
  '母亲催考研并说考不上就回家工作'            ← 确实有压力
```

### 根因

当前规则（`memory_updater.py` 规则 2）：
```
if outcome == "unresolved" and key_points:
    unresolved_topics += all key_points
```

问题出在两个环节：
1. **Summarizer 的 key_points 太细碎**——把"道晚安""询问复习""感叹"都当关键信息提取
2. **规则无过滤**——outcome ≠ "resolved" 就把全部 key_points 倾倒进 unresolved_topics，不管 key_point 是否真的"未解决"

### 候选方案

**方案 A：约束 Summarizer（改 prompt）**
- 在 summarizer 的 prompt 中明确："key_points 只提取真正需要关注解决的问题，日常寒暄/结束语不提取"
- 限制 key_points 数量 ≤ 3 条
- 估算工时：30 分钟

**方案 B：MemoryUpdater 加语义过滤（LLM 判断）**
- 写入 unresolved_topics 前，让 LLM 判断每个 key_point 是否真的"需要解决"
- 代价：额外 LLM 调用，且增加延迟
- 估算工时：2 小时

**方案 C：MemoryUpdater 加规则过滤**
- 新增规则："outcome=unresolved 时，只写入 summarizer 明确标注为 unresolved 的 key_points"
- 修改 summarizer 输出格式，key_points 增加 `type: "unresolved" | "info" | "emotion"` 字段
- 估算工时：1 小时

**方案 D：提高 unresolved 判定门槛**
- 当前 outcome 判定偏松（非 resolved 即 unresolved）
- 在 summarizer prompt 中增加 outcome 定义：
  - `resolved`：问题已解决/情绪已缓解
  - `unresolved`：明确存在未解决的冲突或问题
  - `neutral`：无问题需要解决（日常聊天、道晚安等）
- 让 summarizer 更多判定为 neutral 而非 unresolved
- 估算工时：30 分钟

## 四、问题 3：策略选择严重失衡（严重程度：中）

### 数据

```
逐级释放与反馈循环         71  60%  ← 万能兜底，什么场景都选它
关心vs关注            27  23%
认可情绪 + 表达需求       14  12%
大小二八原则             5   4%
扩大冲突               1   1%   ← 118 条消息只触发 1 次
```

### 根因

查看策略卡 JSON 的 `apply_when` / `not_apply_when` 条件：

- **"扩大冲突"** 卡的条件过于严苛，要求精确匹配特定 need + emotion + intent 组合。在冲突场景中（"你从来都不主动"→intent=complaint, need=ATTENTION），条件匹配失败，fallback 到"逐级释放与反馈循环"
- **"逐级释放与反馈循环"** 卡的条件最宽松（几乎成了 default），导致大部分场景被它拦截
- 6 张策略卡中有 4 张极少被选中

### 连锁影响

策略决定回复风格。策略单一 → 回复风格单一 → 用户感到"AI 只会一种套路"。

在真实 14 天聊天中，应该能自然切换于：
- 共情倾听（"关心vs关注""认可情绪"）
- 主动破局（"扩大冲突"）
- 推进关系（"逐级释放"）
- 轻松调侃（目前无此策略卡）

### 候选方案

**方案 A：放宽其他策略卡的条件**
- 逐个审查策略卡的 `apply_when`/`not_apply_when`，降低门槛
- 让至少 2-3 张卡在每个场景下都能竞争
- 估算工时：2 小时

**方案 B：增加随机性**
- 在 scoring 阶段加入轻微随机扰动（±0.05）
- 让同分段的多张卡有轮换机会
- 代价：可能降低确定性
- 估算工时：30 分钟

**方案 C：引入对话轮次/阶段维度**
- 同一话题的不同阶段（opening/elaborating/closing）使用不同策略
- 例如对话开场用"关心vs关注"，深入后用"逐级释放"
- 需要 conversation_stage 字段已有（message_understanding 已输出），只需在策略条件中引用
- 估算工时：2-3 小时

**方案 D：不做策略选择，交给 LLM 自由发挥**
- 去掉策略卡机制，在 reply_generator prompt 中传入全部 6 张卡的风格描述
- 让 LLM 自己选择最适合的风格
- 代价：失去规则可控性
- 估算工时：1 小时

## 五、问题 4：对话边界 2h-8h 区间空缺（严重程度：低）

### 现象

当前边界规则覆盖了 0-30min 和 30min-2h 区间，以及 >8h 区间。但 **2h-8h 区间没有任何规则匹配**，直接 fallthrough 为 `continue`。

这在实际中影响中等，因为：
- 大部分跨会话间隔要么 < 2h（同一场对话），要么 > 8h（overnight）  
- 2h-8h 的间隔在日常聊天中较少见（午休到晚饭之间可能触发）

### 候选方案

**方案 A：补一条规则**
```
gap > 2h → 直接 close_and_new（不管话题是否切换）
```
- 简化逻辑，2h 以上没聊就算新对话
- 估算工时：10 分钟

**方案 B：维持现状**
- 2h-8h 保持 continue 作为缓冲带，避免过早关闭
- 不修

## 六、优先级建议

| 优先级 | 问题 | 影响 | 推荐方案 |
|--------|------|------|---------|
| P0 | 话题检测失效 | 下游全崩 | B（LLM 检测）或 C（混合） |
| P1 | unresolved_topics 污染 | 长期记忆废掉 | D（提高 unresolved 门槛）+ A（约束 summarizer） |
| P2 | 策略选择失衡 | 回复风格单一 | A（放宽条件）或 C（引入 stage 维度） |
| P3 | 2h-8h 边界空缺 | 偶发巨型对话 | A（补规则）或 B（不修） |
