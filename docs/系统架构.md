# 魔鬼聊天 — 系统架构

Version: 2.1 | 2026-07-26

---

## 一、产品定位

魔鬼聊天是一个**关系策略引擎（Relationship Strategy Engine）**。

核心理念：

> 不让系统学习「如何回复」。
> 让系统学习「什么情绪 + 什么需求 + 什么策略最有效」。
> 回复可以由 LLM 生成，策略才是护城河。

产品形态：Web PWA 分析工具，手机浏览器可访问，局域网部署。

## 三、双轨道架构

系统有两条独立的运行轨道，共享底层策略引擎：

| 维度 | 观测轨道 | 干预轨道 |
|------|---------|---------|
| 触发方式 | WCF 消息自动流入 | 用户打开仪表盘 |
| 运行频率 | 每条消息实时 | 按需 |
| 目标绑定 | 无 | 有 |
| 策略绑定 | 无 | 有 |
| 输出 | 情绪 + 话题 + 会话状态 | 策略 + 建议回复 |
| 效果评估 | 基于自然对话结果 | 基于策略执行结果 |

**观测轨道**：微信消息通过 WCF（WeChatFerry）持续流入，系统自动识别情绪、检测话题、管理会话边界。用户不在线时也在运行。

**干预轨道**：用户打开仪表盘查看待处理消息，系统基于观测积累的数据，一次性给出分析结果和建议回复。

## 四、三层记忆体系

```
消息记忆 → 会话记忆 → 关系记忆
 (短期)     (中期)      (长期)

单条消息    一次话题     跨会话累积
情绪+意图   边界+摘要    规则写入+衰减
```

- **消息层**：理解单条/多条消息的情绪、意图、需求
- **会话层**：检测话题边界，管理对话生命周期，关闭时自动摘要
- **关系层**：跨会话累积关键信息（阶段、信任度、冲突状态、反复话题），支持衰减

## 五、策略抽象层级

策略系统是项目的核心 IP，分为 8 个抽象层：

```
Layer 1: 原则 (Principle)
    — 5 条长期稳定的关系原则，不可被数据推翻
Layer 2: 策略 (Strategy)
    — 8 种可执行策略，原则 → 行为规则
Layer 3: 策略卡 (Strategy Card)
    — YAML/JSON 格式，机器可读的策略指令
Layer 4: 需求模型 (Need Model)
    — 10 种核心需求（被理解、被关注、安全感...）
Layer 5: 情绪模型 (Emotion Model)
    — 13 种情绪标签
Layer 6: 策略矩阵 (Strategy Matrix)
    — 情绪 × 需求 → 策略映射
Layer 7: 决策流程 (Decision Flow)
    — Agent 编排：理解 → 需求 → 目标 → 策略 → 回复 → 评估
Layer 8: 长期学习 (Long-term Learning)
    — 效果评估 → 成功率统计 → 策略权重自优化
```

## 六、Agent 流水线

一次完整的干预分析经过 9 个步骤：

```
她的消息序列
  │
  ▼
① MessageUnderstanding   情绪、意图、需求、话题、burst 模式
  │
  ▼
② NeedRecognizer         需求优先级排序（纯规则）
  │
  ▼
③ GoalPlanner            目标制定（阶段 × 需求 → 单一目标）
  │
  ▼
④ ConversationManager    会话生命周期管理，边界检测
  │
  ▼
⑤ Summarizer             会话关闭时 LLM 生成摘要
  │
  ▼
⑥ ContextBuilder         三层精选上下文组装
  │
  ▼
⑦ StrategySelector       策略匹配（双维度过滤 + 风险惩罚）
  │
  ▼
⑧ ReplyGenerator         策略指令 + 上下文 → LLM 生成回复
  │
  ▼
⑨ ExpressionEnhancer     口语化 + 语气匹配 + 关系阶段感知
  │
  ▼
⑩ Evaluator              策略效果评估（纯规则，8 种成功标准）
  │
  ▼
⑪ MemoryUpdater          长期记忆写入（纯规则 + 衰减机制）
```

其中 ①⑧⑨ 涉及 LLM 调用（3 次），⑤ 在会话关闭时触发（1 次 LLM），其余均为纯规则。

## 七、数据模型

### 关系状态 (relationship_state.json)

```
关系阶段、热度、对方依恋风格
信任程度、亲密程度、冲突状态
近期关键事件、反复话题、未解决问题
策略效果统计（使用次数、成功率）
```

### 会话记录 (conversations.json)

```
活跃会话 + 已关闭会话列表
每条会话：话题、时间、状态、摘要、结果
消息日志（最近内容，供摘要和评估使用）
```

## 八、对外接口

| 端点 | 方法 | 用途 |
|------|------|------|
| `/api/chat` | POST | 非流式分析（单条消息 → 完整回复） |
| `/api/chat/stream` | POST | 流式分析（SSE，逐字输出 + 步骤状态） |
| `/api/observe` | POST | WCF 消息观测入口 |
| `/api/dashboard` | GET | 仪表盘数据（紧急度 + 待处理 + 效果统计） |
| `/api/dashboard/mark-processed` | POST | 标记消息已处理 |
| `/api/conversations` | GET | 对话列表 & 详情 |
| `/api/relationship` | GET/PUT | 关系状态读写 |
| `/api/bootstrap` | POST | 首次使用引导初始化 |
| `/api/health` | GET | 健康检查 |

## 十、技术选型

| 层 | 技术 | 选型原因 |
|----|------|---------|
| 前端 | Next.js + Tailwind CSS | PWA 支持，微信风格 UI |
| 后端 | FastAPI (Python) | 与策略引擎同语言，零桥接成本 |
| 流式 | SSE + asyncio.Queue | 用户边等边看，感知延迟降低 |
| LLM | DeepSeek API (opencode.ai) | 性价比高 |
| 存储 | JSON 文件 + asyncio.Lock | 单用户 MVP，无需数据库 |
| 消息源 | WCF (WeChatFerry) | 微信 PC 客户端 hook，只读 |
