Version: 2.0 | 2026-07-26 | 作者: Saber (PM)

## 〇、产品定位

**魔鬼聊天不是一个聊天话术库，而是一个关系策略引擎（Relationship Strategy Engine）。**

核心原则（来自伟大蓝图）：

> 不要让系统学习「如何回复」。
> 让系统学习「什么情绪 + 什么需求 + 什么策略最有效」。
> 回复可以由 LLM 生成，策略才是真正的护城河。

产品形态演进路径：

```
CLI 原型（已完成）
  → Web PWA 分析工具（已完成）
    → WCF 实时监听 + 仪表盘（当前方向）
      → 个人化策略自优化（远期）
```

### 1.2 三层记忆体系

```
Message → Conversation → Relationship Memory
  短期       中期              长期

消息理解      会话引擎           MemoryUpdater
情绪+意图     边界检测+摘要       规则写入+衰减
(单条)       (一个话题)         (跨会话累积)
```

### 1.3 两条轨道的并行架构（v2.0 新增）

| 维度 | 观测轨道 | 干预轨道 |
|------|---------|---------|
| 触发方式 | WCF 消息自动流入 | 用户打开仪表盘 |
| 运行频率 | 每条消息实时 | 按需 |
| Goal 绑定 | 无 | 有（策略目标） |
| Strategy 绑定 | 无 | 有（策略卡） |
| 输出 | 情绪 + 话题 + 会话状态 | 策略 + 建议回复 |
| 会话管理 | 边界检测 + 自动摘要 | 同左 |
| Evaluator | 基于自然对话结果 | 基于策略执行结果 |

### 1.4 策略抽象层级（来自伟大蓝图）

```
Layer 1: Principle（原则）— 5 条，长期稳定
Layer 2: Strategy（策略）— 8 种，原则 → 可执行行为
Layer 3: Strategy Card（策略卡）— YAML/JSON，机器可读
Layer 4: Need Model（需求模型）— 10 种核心需求
Layer 5: Emotion Model（情绪模型）— 13 种情绪
Layer 6: Strategy Matrix（策略矩阵）— 情绪 × 需求 → 策略
Layer 7: Decision Flow（决策流程）— Agent 编排
Layer 8: Long-term Learning（长期学习）← v2.0 正在建设
```

## 五、下一步方向

基于伟大蓝图的第 8 层（长期学习）已经搭建好基础设施（Evaluator + strategy_effectiveness）。下一步的核心是**接入真实数据源**：

### 优先级 1：WCF 集成

```
微信 PC 客户端 → WCF SDK → MessageBuffer → 观测轨道 → 仪表盘
```

这是让系统从「手动输入工具」升级为「自动监听助手」的关键一步。接入后：
- 消息自动流入，不再需要手动复制粘贴
- Evaluator 获得完整的 before/after 数据（她能看到的你的回复 + 她的回应）
- 表情包/图片信息天然获取
- 多句连发自然聚合

### 优先级 2：策略自优化

当 `strategy_effectiveness` 积累足够数据后（每个策略 ≥ 20 次使用），StrategySelector 可以结合历史成功率调整推荐权重。当前已收集数据结构：

```json
{
  "strategy_effectiveness": {
    "共情": {
      "total_uses": 15,
      "successes": 12,
      "success_rate": 0.80,
      "last_used": "2026-07-26"
    }
  }
}
```

当某个策略在特定情绪/需求组合下成功率显著低于平均值时，系统可以降低其推荐优先级。这就是蓝图所说的「策略才是护城河」——数据累积越久，系统越懂你的她。

### 优先级 3：衰减机制接入

`MemoryUpdater.apply_decay()` 已实现但从未调用。建议在每次后端启动时执行一次，基于 conversations.json 中各 topic 最后出现时间计算 ages dict。改动量约 10 行。
